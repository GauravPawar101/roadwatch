# RoadWatch — Environment variables and where to find their values

This file lists the environment variables you should set for local development, where to set them, and where to find example/default values.

1) CORS configuration
- CORS_ORIGIN / CORS_ORIGINS
  - Purpose: Whitelist origins allowed to access the APIs (used by `apps/gateway-api` and `backend-api`).
  - Example value (local dev): `http://localhost:5173,http://localhost:3000`
  - Where to set: `apps/gateway-api/.env` or the service-specific `.env` file; can also be exported in the repo root `.env` read by `start-all`.
  - Notes: If you use credentialed requests (`credentials: 'include'`), do NOT set a single wildcard `*` here in production.

2) Gateway API / Frontend
- PORT
  - Purpose: Host-facing port for the gateway API (default example: `3100`).
  - Where to find example: `.env.example` in repo root (PORT=3100).

- VITE_PORT, VITE_API_BASE
  - Purpose: Frontend dev server port and API base URL used by the Vite app.
  - Example: `VITE_PORT=5173`, `VITE_API_BASE=http://localhost:3100`
  - Where to set: frontend `.env` or repo root `.env`.

3) Backend API
- BACKEND_PORT
  - Purpose: Port the backend-api listens on (default `4001`).
  - Where to find example: `.env.example` (BACKEND_PORT=4001).

4) Cassandra (required for gateway & some services)
- CASSANDRA_CONTACT_POINTS
- CASSANDRA_KEYSPACE
- CASSANDRA_LOCAL_DC
  - Purpose: Cassandra connection details.
  - Example: `127.0.0.1:9042`, `roadwatch`, `datacenter1`
  - Where to find example: `.env.example` and `.env.template` in repo root.

5) Kafka / Messaging
- KAFKA_BROKERS (or KAFKA_BROKER)
- KAFKA_GROUP_ID
  - Purpose: Broker list and consumer group ids for Kafka-based services.
  - Example: `localhost:29092` or `127.0.0.1:9094`
  - Where to find example: `.env.example` or service-specific README/configs.

6) Redis
- REDIS_URL (or UPSTASH_REDIS_REST_URL & UPSTASH_REDIS_REST_TOKEN)
  - Purpose: Redis connection used by some services.
  - Example: `redis://127.0.0.1:16379/0`
  - Where to find example: `.env.example`.

7) Auth / Secrets
- JWT_SECRET
  - Purpose: Local JWT signing secret used by the gateway for auth flows.
  - Where to set: `apps/gateway-api/.env` or root `.env`.
  - Example (dev): `local_development_cryptographic_secret` (see `.env.example`).

8) Misc / Service overrides
- SERVICE_NAME, LOG_LEVEL, other KAFKA/UPSTASH overrides
  - Purpose: Per-service runtime configuration; check the specific service file or `.env.example`.

Where to find examples and defaults
- `.env.example` (repo root): primary source of example values for local development.
- `.env.template` (repo root): containerized defaults and notes.
- Service-specific `.env` files: `apps/gateway-api/.env` (create if missing) and `backend-api/.env` (optional).

How to apply
- For quick local dev, copy `.env.example` to `.env` in the repo root and edit values.
  - `cp .env.example .env` (bash) or `copy .env.example .env` (PowerShell)
- Or add service-specific env files (recommended):
  - `apps/gateway-api/.env` → set `CORS_ORIGIN`, `PORT`, `JWT_SECRET`, Cassandra/Kafka overrides
  - `backend-api/.env` → set `BACKEND_PORT`, `CASSANDRA_*`

Recommended CORS local value (paste into `apps/gateway-api/.env`):
CORS_ORIGIN=http://localhost:5173,http://localhost:3000
